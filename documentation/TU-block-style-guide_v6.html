Section 01 — The Landscape

The gap in context

Adoption among students has outpaced institutional policy by a wide margin. That gap is not unique to us — it is a sector-wide pattern that policy has not yet resolved.

The practical question is not whether staff use these tools, but whether they do so with support and guardrails.

Block 08 · type-lesson-mistake
Section 02 — Capability
01

Start with the workflow

The tools that stick are the ones that remove a step someone already resents. Begin with a task the team already does every week, not with the technology.

Common mistake
Choosing a tool first and then hunting for a problem it might solve. This produces impressive demos and very little adoption.

Section 03 — People

Principles we agreed

  • Approved tools first — University data stays within policy.
  • Start with workflows that already cause friction.
  • Document use cases properly so investment requests have evidence.
  • Share what works across departments rather than rebuilding it.
  • Keep a human check on anything that reaches a student or applicant.

Block 13 · type-lesson-takeaway
Section 04 — Projects
02

Prove it small

Every project above began as a contained test with a defined success measure. None required new budget to reach a demonstrable stage — which is precisely what makes the case for the next stage credible.

Key takeaway
A working prototype is a stronger business case than a proposal document.

Block 15 · type-opp-blockers
Section 05 — Position

Opportunities and blockers

Opportunities
  • Upgrade Copilot licences for defined roles
  • Build documented use cases for investment requests
  • Adopt low-risk complementary tools
  • Automate departmental workflows with Power Automate
Blockers
  • ICT cannot assess alternative tools at present
  • Director-level sign-off needed for new tooling
  • Personal data processing requires extra scrutiny
  • Budget cycles slow adoption regardless of merit
