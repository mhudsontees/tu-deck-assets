Overview

Branded slide decks, built in the browser

This is a system for producing Teesside-branded presentations as web pages rather than PowerPoint files. You write your content in a plain text template, paste it into Claude, and get back a finished deck that opens in any browser, works on a phone, and exports to PDF — already correct on brand, because the styling is applied centrally rather than by hand.

The important idea is a separation between content and styling. You supply the words. The system supplies the fonts, colours, spacing and layout. Neither of us has to think about the other's half. That separation is what makes the brand hold together across everyone who uses it.

No PowerPoint
Decks are self-contained web pages. Nothing to install, nothing to keep in sync with a master file.
Brand by default
FS Lola, University gold and the approved greys are applied automatically. There is no way to get them subtly wrong.
27 ready blocks
Timelines, stat cards, charts, tables, quotes and more — each already designed, responsive and print-tested. Plus an attribution modifier.
The core principle
You write content. The system applies the design. Because the styling lives in one central file rather than inside each deck, improving it once improves every deck that links to it — without anyone reopening a file.
01
What the system does

Each deck is a single HTML file — a web page that behaves like a presentation. It fills the screen, moves one slide at a time with the arrow keys or a swipe, and carries the University logo, footer and slide numbering without you positioning anything.

Built in from the start

CapabilityWhat it means in practice
Full-screen presentingOpen the file, press F11 or use full screen, and present. Arrow keys or spacebar to advance; swipe on a tablet or phone.
PDF exportA Save as PDF link in the footer prints every slide as a page, in order, at full quality. Charts stay sharp because they are drawn, not photographed.
Works on mobileSlides reflow for a narrow screen — columns stack, tables scroll, text resizes. Useful for reviewing on the way to a meeting.
Shareable as a link or fileEmail the file, put it on SharePoint, or host it and send a URL. No viewer software required at the other end.
Accessible by constructionReal text rather than images of text, sensible contrast, and required alternative text on photographs.

Charts and diagrams are drawn, not pasted

Where a normal deck would contain a screenshot of a chart, these decks contain the chart itself, drawn in code. It stays crisp at any size, prints properly, and picks up brand colours automatically. The practical effect is that you never have to rebuild a chart in Canva, export it, and paste it back in.

02
What you never have to do again
  • Open a PowerPoint file. No master slides, no theme drift, no "which version is the current one".
  • Pick a font or a colour. Both are decided centrally and applied for you. Off-brand values are not available to choose.
  • Align anything by dragging. Spacing and alignment come from the layout, not from the mouse.
  • Rebuild a chart as an image. Charts are code, so they scale and print cleanly.
  • Reformat for mobile or for print. Both behaviours are already built into every block.
  • Chase a style update. Central improvements reach your deck on their own.
Why brand integrity holds
In a PowerPoint file, brand rules are a convention people follow — or quietly don't. Here the colours, fonts and weights are defined once, in one place, and every block refers back to them. A deck cannot drift off brand by accident, because the brand values are not stored in the deck at all.

How a deck gets made

There are only two inputs: the template (which carries the block patterns and the link to the house style) and your content (your title, sections and slides). You paste both into Claude, and it assembles the finished page.

Claude builds from the template in front of it — it does not fetch anything from the University website while generating.

What this means for you

Because the deck is assembled from a template rather than designed from scratch each time, two people writing about different subjects still produce decks that look like they came from the same organisation. You are choosing which block to use and what it says — not what it looks like.

Keep your content file
Save the filled-in template you pasted in — your "generation file". If you want to change a deck later, or rebuild it against an improved template, you re-run that saved content rather than editing the finished HTML by hand.

Where the styling lives

The house style — every colour, font, spacing rule and block layout — lives in a small set of files hosted on the University website. Your deck does not contain them. It refers to them, the same way a web page refers to its stylesheet.

Dashed border = a live link, not a copy. This is the mode you will use.

The consequence, and it is the useful bit

Because your deck holds a link rather than a copy, any central improvement — a clearer chart style, a better mobile layout, a corrected colour — appears in your deck the next time you open it. You do not re-download anything and you do not rebuild your deck.

The one condition is that a linked deck needs to reach the University website when it opens. On campus, on Eduroam or on VPN this is automatic. Genuinely offline, it falls back to a plain font — see section 07.

The block library

A block is a pre-designed slide type. Rather than building a layout, you pick the block that matches what you are trying to say. There are 28, and a separate style guide deck shows every one of them rendered, numbered so you can refer to them ("use block 07 for that").

Block 11 — standard bullets is the everyday slide: a heading and body text as bullet points. Use it unless another block fits better. Everything else is a specialised alternative.

Two things move independently, and knowing which is which explains almost every question people have about the system.

What changesWhere it livesWhat you do
Appearance — colours, spacing, how a block looksThe hosted style fileNothing. It reaches your deck automatically.
New or changed block typesThe templateDownload the latest template before your next deck.

The shared slide library

Alongside the template there is a curated library of reusable slides — material that has proven useful more than once, such as sector statistics, standing definitions or recurring process diagrams. It is maintained centrally and dipped into occasionally rather than used for every deck.

The library grows from your work. If you build a slide you think colleagues would reuse, flag it. Matt reviews suggestions and, where a slide is genuinely reusable, adds it to the shared set with a stable reference so it can be found again. Deciding what earns a place in the library is a single-owner job on purpose — it is what stops a shared set turning into an unsorted pile.

Why one person holds the pen
Anyone can author a deck and anyone can suggest a slide for reuse. Only one person edits the shared style and the shared library. That is the whole governance model, and it is what keeps a system used by several people looking like it was made by one.
07
Limitations and things to know

Images need a connection, and are discouraged

Photographs are not stored inside the deck. They are uploaded through the University upload form, which returns a web address, and the deck points at that address. Two consequences: an image slide needs a connection to display, and an offline copy will show a gap where the picture should be.

Beyond that, images are deliberately not encouraged. Most of what people reach for a picture to do — charts, diagrams, process flows — is better done by a block, which stays sharp, prints properly and matches the brand. When you do use one, keep it modest in size (around 960×540 is ample for a slide) and always write proper alternative text describing what it shows.

Offline copies are frozen

If you genuinely need a deck that works with no connection — a venue with no wifi, a memory stick — ask and one can be produced. It bundles the styling inside the file, so it works anywhere, but it is a snapshot: it will not receive later improvements. Refreshing it means producing it again.

Which AI tool you use matters

The template is designed to be filled in by Claude. Because the deck is mostly structure and labels rather than design code, other assistants will often produce something workable — but there are failure modes that look fine on screen and are not: an assistant may quietly add its own styling, or pull in an external resource, either of which breaks the brand link or the offline behaviour. If you use a different tool, the three checks in the quickstart guide are worth running. Note also that for University data, Copilot is the only approved tool.

Other boundaries worth knowing

  • Video is not supported. Link out to it instead.
  • Slide transitions and animation are minimal by design — one clean movement between slides, nothing that misbehaves in PDF.
  • Very long decks get unwieldy; break beyond about 40 slides into two.
  • Editing the finished HTML by hand is not the way to change a deck. Change your content file and regenerate — the built file is a disposable output.
08
Questions you may have
Do I need to install anything?
No. Decks open in the browser you already have. There is nothing to install, licence or keep updated.
Can I still send someone a PowerPoint?
Not directly — but you can send the PDF export, which is usually what people actually want. If a genuine .pptx is required for an external process, that is a conversion job, so raise it early.
What if I want a layout that is not in the 27 blocks?
Ask. If it is a one-off, there is usually a block that gets close. If it is something several people would use, it becomes a candidate for a new block type.
My deck looks unstyled — plain text on white. What happened?
It cannot reach the hosted style file. Check you are on the University network or VPN, then reload. If that does not fix it, the link line may have been altered during generation — regenerate from your content file.
The font looks wrong but everything else is fine.
The layout has loaded but FS Lola has not. Almost always a connection issue; reconnect and reload.
Can two of us work on the same deck?
Not simultaneously. Decks are authored individually. Share the content file if you need to hand one over.
Will my old decks break when the style is updated?
No. Improvements are additive, and anything that would break existing decks is published under a new file name so older decks keep pointing at the version they were built against.

Glossary
Block
A pre-designed slide type. You choose the block; it supplies the layout.
Template
The plain text file you paste into Claude. Contains the block patterns and the link to the house style.
Generation file
Your filled-in template — the content you pasted in. Worth keeping so a deck can be rebuilt later.
Linked deck
A deck that refers to the hosted style files rather than containing them. The default, and the mode that stays up to date.
Offline copy
A deck with the styling bundled inside it. Works with no connection, but frozen at the moment it was made.
CSS
The stylesheet language that holds the house style — colours, fonts, spacing, layout.
CDN
Content delivery network. In this context, the University web hosting that images are uploaded to and served from.
FS Lola
The University's primary typeface, used for headings and titles.
Slide library
The curated set of reusable slides maintained centrally, separate from your own decks.
